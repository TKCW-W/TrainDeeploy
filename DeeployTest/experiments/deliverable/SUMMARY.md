# Deliverable — SpeechNet on-device fine-tuning: MaxPool-backward options + ZO

Single-step on-device (Siracusa/GVSoC) fine-tuning, **fresh fixtures generated by Onnx4Deeploy** for each run,
`--plotMemAlloc`, frozen-BN recipe, `--l2 2000000` (2 MB Siracusa L2), `random-max` tiling. Branches:
TrainDeeploy `feat/BP+ZO`, Onnx4Deeploy `feat/BP+ZO`.

## Results

| exp | MaxPool backward | result | train-net L2 peak | vs recompute |
|---|---|---|--:|--:|
| **exp1** `exp1_BP_argmax_off` | **recompute-from-X** (argmax-mask OFF; shipped kernel) | PASSED, 0 err | **1,735,180 B** | — |
| **exp2** `exp2_BP_argmax_on` | **argmax-mask** (ON; our optimization) | PASSED, 0 err | **1,511,308 B** | **−13.0 %** |
| **exp3** `exp3_ZO` | none (forward-only ZO) | PASSED, bit-exact 0/2 | **789,688 B** | **−54.5 %** |

Each folder holds `REPRODUCE.md` (exact commands), `logs/sim.log` (with the `Errors`/`PASSED` line),
`results/memory_alloc_*.html` (memory plots for the train and optimizer graphs), and `fixture/` (the exact
ONNX + npz used).

## What each option is (ownership)

- **Shipped (`TrainDeeploy feat/speechnet-training`, `Onnx4Deeploy devel`):** the device MaxPool forward is
  **single-output**, and `PULP_MaxPoolGrad2d` **recomputes the argmax by rescanning the forward input X**
  (`MaxPoolGrad(dY, X)`). Onnx4Deeploy `devel` avoids MaxPool on device by using **AvgPool**; there is no
  shipped MaxPool-training exporter path.
- **exp1 recompute (ours, graph adapter):** `_rewire_maxpoolgrad_recompute` rewrites ORT autodiff's
  2-output MaxPool + `MaxPoolGrad(dY, Indices)` into the shipped kernel's single-output +
  `MaxPoolGrad(dY, X)` contract. It **reuses** the shipped recompute kernel — it is *not* a second recompute
  algorithm, just the exporter↔kernel bridge. Cost: the block-0 activation X (~314 KB) stays live to backward.
- **exp2 argmax-mask (ours, optimization):** alternative branch of the same exporter step — inserts
  `MaxPoolArgmax` (forward emits a small within-window offset mask) + `MaxPoolGradMask` (backward reads the
  mask), so X is freed after the forward pass. Works **directly on the shipped single-output MaxPool**; it does
  **not** depend on the recompute path. → the −13 % L2 win.
- **exp3 ZO (ours):** forward-only MeZO — no backward, no MaxPool gradient, no activation stash → the smallest
  footprint (−55 %).

## Notes
- The `--maxpool-argmax-mask` flag is the single toggle between exp1 (off) and exp2 (on); no other code change.
- Static allocation ⇒ the L2 peak is independent of `--n-steps`; a single step is a valid memory-fit probe.
- Fixture naming matters: the `-o`/`-t` train dir **must contain `_train`** so the sibling `_optimizer` SGD
  graph is auto-generated and resolved (see `BP_FLOW.md` / `ZO_TECHNICAL_REPORT.md`).
