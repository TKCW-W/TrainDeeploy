# exp1 — FINDING: Option A fixes the ORT reference; device full-training-frozen-BN is bit-exact

**Date:** 2026-07-28
**Result:** ✅ **Option A works.** On the full-model, frozen-BN training path, the on-device (Siracusa/GVSoC)
per-step loss now matches the (fixed) ORT reference **bit-exact** — smoke test `Errors: 0/36`, every step
`diff ≈ 0` (≤ ~1e-6, TOL 1e-3).

## Recap of the issue
The runner compares the device's per-step loss trajectory against `testLossRef[]` (baked into
`testoutputs.h` from `outputs.npz['loss']`). That trajectory is produced by the SpeechNet exporter's
`create_training_test_data`, which ran the whole training loop **in ORT on `network_train.onnx`**. For full
training the BN affine (γ/β) is trainable, so ORT uses `BatchNormInternal(training_mode=1)` = **live-batch**
BN, whereas the device (`BN_FROZEN_STATS=ON`) trains with **frozen** pretrained stats. Every step disagreed
→ false `Errors: 2160/2160`. The device was correct; the *reference* was wrong.

## What we changed (Option A)
`Onnx4Deeploy/onnx4deeploy/models/speechnet_exporter.py`:
- New `_frozen_pytorch_reference(...)`: builds the exported torch model, loads the fixture's exact initial
  weights (`init_map`), sets `model.eval()` (**frozen BN**, γ/β still trainable), and runs the **identical**
  device loop — same window order (`mb % data_size`), **SUM** gradient accumulation, plain `SGD(lr)` (no
  momentum/wd) → `w ← w − lr·Σ gradᵢ`, one step per `n_accum`. Emits the per-step losses + updated weights.
- `create_training_test_data` is **gated on `bn_frozen_stats`**: when set, use the frozen PyTorch reference;
  otherwise the original ORT loop (unchanged). No device-side change — the fast fused
  `BatchNormInternal(frozen)` kernel + `g_bn_frozen_stats` C-flag are untouched.

### Why Option A over Option B
- **Option A** (this): fix only the *reference* (the actual bug). Zero device latency/memory cost.
- **Option B** (decompose frozen BN into `Sub/Mul-const → Mul γ → Add β`): makes the graph itself frozen and
  retires the C-flag, but with no fp32 fusion pass / affine kernel it runs **un-fused → ~4× BN-layer
  activation DMA** on the early large-activation blocks, and clawing that back needs a new fused kernel.
  Reserved as a future "frozen-BN as a first-class graph construct" cleanup.

- Fixture: `Tests/Models/Training/SpeechNet/speechnet_train_fullfrozen_smoke` — S01 vocalized fold 3, batch 1,
  **full model**, **frozen BN**, data_size 18 (2/class), n_epochs 2, **n_accum 4**, lr 3e-4 → 36 forward
  passes / 9 optimiser steps. Exported with `--bn-frozen-stats`; reference generated by the new frozen path
  (`[exp1/Option A] frozen-BN PyTorch reference — 36 losses`).
- Run: `deeployTrainingRunner_tiled_siracusa -t ...speechnet_train_fullfrozen_smoke --n-steps 9 --n-accum 4
